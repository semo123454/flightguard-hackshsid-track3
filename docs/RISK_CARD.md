# 风险卡

## 预期用途

帮助航空公司运行、机场协调和旅客服务人员整理模拟机场扰动信息，比较历史背景，生成核查清单与待审草案。适用于培训、流程设计和离线演示。

## 明确不适用

不能用于真实航班安全判断、放行、取消、调度、维修、赔付或正式旅客通知。不能代替签派、机务、飞行、运行控制、安全或法律专业人员。当前版本不接入实时天气、逐航班、飞机位置、机组、登机口或保障资源系统。

## 主要风险

1. 月度历史与当前时段粒度不同，可能产生错误类比。
2. 输入由人勾选风险信号，错误输入会导致错误分级。
3. 规则覆盖有限，未见过的安全情形可能超出系统能力。
4. “低风险”可能被误读为“安全已确认”。
5. 文案虽然标记为草案，仍可能被用户绕过审核发布。
6. 脱敏基于常见文本模式，不能保证识别所有个人信息形式。

## 控制措施

- 页面、证据和草案统一标注“模拟”。
- 来源冲突、来源不可靠和安全问题触发无法判断或停止机制。
- 高风险要求多个独立信号和至少两个可靠来源。
- 重大决定只返回人工审批边界，不提供执行接口。
- 草案不具备发送能力，旅客信息明确“未发送、须人工审核”。
- 只持久化白名单字段，并在持久化前脱敏。
- 人工接受、修改和拒绝均留痕，修订版关联原记录。

## 监控指标

- 安全边界违规数：目标为 0。
- 无来源数字占比：目标为 0。
- 草案未经审核发布事件：目标为 0。
- 冲突未解决仍给出确定结论的次数：目标为 0。
- 证据完整率、人工接受率、修改原因分布和重复错误率。
- 从事件输入到生成首个核查清单的时间。

## 停用条件

发现系统给出真实操作指令、隐私信息被持久化、规则与现行运行程序冲突、数据源时间或口径不可确认、或出现未覆盖的安全问题时，应立即停用自动建议，仅保留信息整理，并交由专业负责人处理。

## 责任

模型负责人维护规则和测试；数据负责人维护来源、时间和口径；运行负责人批准试点与升级流程；各专业岗位对最终业务决定负责；旅客服务负责人审核所有外发文字。
